What changes from today's screens

  • Each schedule says what it runs on: "Claude Code · Haiku · your Claude plan" or "Claude Sonnet 5.5 · your key". Today a schedule silently follows the project's newest session.
  • The New schedule dialog gets a "Runs on" row with the same model button as Code, including the Your agent tab. It starts on "Same as the project's last session", which is what happens today.
  • A run that the plan stopped shows the program's own words in its history, says the project was not touched, and offers "Run again" or "Run it on another agent". A signed-out program says "Sign in to …" with the button.
  • Installing packages in a session on a program. Claude Code or Codex cannot reach a package index, and this mockup keeps it that way (see the question below). When it needs packages, a card offers "Install what the project lists": Wasify AI runs npm install or pip install -r requirements.txt itself, in Wasify AI's own sandbox, where your Claude or ChatGPT sign-in is out of reach. Then the program carries on.

The question for the owner: how packages are installed

  • A (recommended): installs run outside the program, as above. The program's sandbox never reaches a package index. Safe: a hostile package's install script cannot see your sign-in.
  • B: let the program reach the package indexes (npm, PyPI) itself. Simplest, and it works without asking. But the program's sandbox can read your sign-in, and a hostile package can carry its own publishing key and publish your sign-in as a package. The indexes are on our list because no key is inside the sandbox; with a program, one is.
  • C: nothing new: you run installs yourself in the Terminal tab (works today).
